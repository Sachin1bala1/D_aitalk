# Microsoft Partner Center Submission Checklist

Last updated: 2026-05-01

## Goal

Prepare the non-code assets and metadata required to submit Daitalk to Microsoft Partner Center without last-minute scrambling.

Use [partner-center-evidence-packet-guide.md](./partner-center-evidence-packet-guide.md) first when you need to assemble the final internal evidence bundle and signoff record for the exact candidate being submitted.

## Working rule

For each item below, record one of:

- ready
- blocked
- not applicable for this release

Do not leave items implied by memory alone.

## App identity

- final product name confirmed
- short description confirmed
- long description confirmed
- package identity and publisher identity confirmed
- release version confirmed

## Store listing assets

- app icon set prepared in required sizes
- screenshots prepared from release-quality builds
- optional promotional art prepared if needed
- support URL verified
- privacy policy URL verified
- publisher contact email verified

## Listing content

- value proposition text written
- core feature bullets written
- desktop-only behavior described where relevant
- AI/provider behavior described accurately
- local-data and privacy claims align with the app

## Compliance and declarations

- privacy disclosure text finalized
- local storage behavior documented
- external network/provider use documented
- content rating or age-rating path identified
- export control or special declarations reviewed if applicable

## Release notes

- "what's new" text prepared
- known limitations text prepared if needed
- support escalation path defined for launch issues

## Packaging inputs

- package version matches release plan
- packaging artifact path recorded
- signing path recorded
- install and uninstall validation evidence attached

## Go/no-go checks before submission

- no unresolved clean-install blocker
- no unresolved update blocker
- no unresolved uninstall blocker
- no unresolved privacy mismatch
- no unresolved release CSP or capability blocker

## Evidence to attach internally

- completed validation report
- release preflight output
- final package path
- final signing confirmation
- screenshots source list
- final Store listing text source
